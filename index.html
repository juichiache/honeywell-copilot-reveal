Slide 1 - Title

Case Study: Why Copilot Stays in Search Mode

Honeywell: From Copilot training to Copilot as the operating system for engineering work

Slide 2 - The Reality

Senior Engineers Still Use Copilot Like Advanced Search

Key message: The default state of Copilot adoption is search mode.

Most of the org treats Copilot like an advanced Google search.
Bottom line: Copilot stays in Q&A mode when work has no durable system for Copilot to operate against.
Slide 3 - The Adoption Gap

Knowing the Mechanics != Running Work Through Copilot

Key message: Training can teach what Copilot can do, but it does not automatically change how engineering work is executed.

The average one does not understand agents or skills.
Agents are still confusing.
Bottom line: Feature awareness is not workflow transformation.

Slide 15 - Adoption Model

How Copilot Adoption Actually Evolves

  • Awareness: training, demos, capability understanding
  • Exploration: prompt-based usage, Q&A, code help
  • Friction: no durable workflow, context, or structure
  • System Installation: specs, decisions, repo, templates, instructions
  • Workflow Integration: Copilot embedded in daily execution
  • Scale: pattern reused across teams and projects
Slide 16 - Reusable CSA Framework

Externalize -> Structure -> Install -> Execute -> Repeat

  • Externalize: bring real artifacts, decisions, and constraints into view
  • Structure: turn scattered thinking into design and boundaries
  • Install: create a system Copilot can work against
  • Execute: use Copilot inside the system
  • Repeat: scale the pattern across projects
